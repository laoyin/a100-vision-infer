⑩ 投机解码：让一次前向，吐出好几个 token

Decode 阶段每个 token 都要把整份权重读一遍，典型“访存受限”。投机解码（Speculative Decoding）的思路是：先用一个又小又快的草稿模型一次猜出好几个 token，再让目标模型一趟并行验证——猜对的全收，白赚的那一个也收下。本项目的草稿模型就是 MTP（Multi-Token Prediction）单层头。

为什么能加速？

普通 decode：1 次前向 = 1 个 token。投机查询：1 次前向 = 最多 K+1 个 token。因为读权重只读了一遍，多算几个 token 的边际成本很低。拖动下面的“窗口 K”看差距（假设全部命中）：

每轮：committed = accepted + 1。这个 +1 就是“无论草稿对不对，目标模型那一步总会多给出一个正确 token”。
这就是 include/avi/speculative.h · GreedyVerification::committed_inputs() 返回的 accepted+1；命中率 = accepted / proposed，也是 worker 里 mtp_stats 事件上报的 accepted/proposed。

关键点 1：草稿模型长什么样

草稿不是另训一个大模型，而是目标模型自带的 MTP 头（配置 mtp_num_hidden_layers=1、共享 embedding）。它把“下一个 token 的 embedding”和“上一层已验证的 hidden”拼起来，过一层 full_attention + SwiGLU，就猜出下一个 token：

// src/speculative.cpp · mtp_step()
auto x = linear(at::cat({ norm(embeddings, "mtp.pre_fc_norm_embedding"),
                          norm(hidden,      "mtp.pre_fc_norm_hidden") }, -1),
                "mtp.fc");                                    // 拼接 + 融合投影
x = x + full_attention(norm(x, "mtp.layers.0.input_layernorm"),
                       positions, 0, "mtp.layers.0.self_attn", {}, true,
                       &drafts_[active_].state);               // 单层注意力
auto n = norm(x, "mtp.layers.0.post_attention_layernorm");
x = x + linear(at::silu(gate) * up, "mtp.layers.0.mlp.down_proj", true); // SwiGLU
return norm(x, "mtp.norm");
因为它只有 1 层，非常轻，所以适合用 CUDA Graph 固化：--mtp-draft-graph 会先热身 2 次再 capture，之后每步 replay()。前提是窗口 --mtp-tokens>0。

关键点 2：目标模型怎么“一趟验证”

把「草稿已确认的前缀 + 全部提案」拼成一段（长度 1+count），让目标模型一次前向算完，再逐位比对：

// src/speculative.cpp · speculate()（核心几行）
int count = std::min(options_.mtp_tokens, budget - 1);   // 最多猜几个
std::vector<int64_t> inputs{pending}, proposals;
auto hidden = previous;
for (int i = 0; i < count; ++i) {
  hidden = draft_one(inputs.back(), position + i, hidden);        // 单层 MTP 猜一个
  int64_t token = gather_candidates(local_candidates(hidden))[0];
  proposals.push_back(token); inputs.push_back(token);
  if (命中 eos) break;
}
verifying_ = true;
auto target_hidden = step(embeddings, positions);                 // ← 目标模型一趟并行验证
GreedyVerification decision(proposals, budget, eos);
for (int i = 0; !decision.done; ++i)
  decision.observe(select ? select(values.narrow(0, i, 1))
                          : choices.at(i));
int committed = decision.committed_inputs();                      // = 命中数 + 1
验证是贪心的：verifying.h 里 observe() 只要发现 target != proposals[i] 就 done=true 立刻停。因此要求 temperature=0——需要随机采样时 worker 会直接报错，改用非 MTP 的 worker。

关键点 3：猜错了怎么“回滚”

验证时目标模型把 1+count 个位置都算了一遍，KV Cache 和线性注意力的递归状态里混进了“尚未确认的未来”。一旦某位被拒，必须把状态回退到“已确认前缀”：

// src/speculative.cpp · 回滚被拒绝的未来
for (size_t layer = 0; layer < states_.size(); ++layer) {
  auto& state = states_[layer];
  if (state.key.defined())                                        // 全注意力层：
    state.length = consumed + committed;                          //   把 KV 截断到已确认长度
  if (state.recurrent.defined()) {                                // 线性注意力层（Gated DeltaNet）：
    state.recurrent.copy_(verify_recurrent_[layer].select(0, committed - 1));
    state.conv.copy_(verify_conv_[layer].narrow(-1, committed, state.conv.size(-1)));
  }
}
draft.state.length = draft_old;   // 丢弃草稿的“假设 KV”，用已验证的 hidden 重建
线性注意力层没有 KV 可以“截断”，只能靠验证时同步保存的 verify_recurrent_ / verify_conv_ 快照恢复到第 committed 步。这套“投机 + GDN 回滚”在 第 8 课对应的 optimized_test.cpp 里有专门断言（GDN accepted-prefix state）。

一句话抓住：投机解码 = “用小模型批量猜，用大模型一趟判”。本项目的特别之处在于：草稿是目标模型自带的 单层 MTP；验证时一定要把被拒的未来从 KV Cache 与线性注意力递归状态里干净地回滚掉——这也是它与普通 Transformer 投机解码最大的不同。项目本身仍是实验版，收益以实测为准。
