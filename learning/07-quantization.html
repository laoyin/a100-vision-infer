⑦ 量化 FP8：用 8 个 bit 装下一个浮点数

模型权重太多，用 BF16 存不下。本项目把权重压成 FP8（E4M3FN）——每个数只占 1 字节，显存直接减半，计算时再解码回 BF16。代价是精度。下面输入一个数字，实时看它被编码成哪 8 个 bit、还原回来差多少。

注意格子不是等距的：靠近 0 的地方很密、越往大越稀。这就是“只有 3 位尾数”的代价。高亮的是你输入的数落到的那个档。

同一行里几个数一起量化

同一行共用同一个 scale，所以接近 0 的数相对误差更大；超过 448×scale 的数会被“夹”到最大档。

对应 tools/format_utils.py · decode_fp8()：e=(b>>3)&15, m=b&7；value = e==0 ? m×2⁻⁹ : 2^(e−7)×(1+m/8)；最大正数 448；e=15,m=7 是 NaN。

编码规则：一位符号 + 四位指数 + 三位尾数

E4M3FN ： 1 位符号 · 4 位指数（偏置 7）· 3 位尾数　—— 没有无穷大，最大 1.75×2⁸ = 448
// tools/format_utils.py · quantize_fp8()（编 码 侧）
scales = max(|每行|) / 448            # 每个输出行一个 FP32 scale
target = min(|x| / scale, 448)        # 缩放到 FP8 能表示的范围
upper = searchsorted(_FP8_POSITIVE, target)
lower = upper - 1
# 选更近的那个；一样近时选“偶数”code（ties-to-even）
use_upper = (du < dl) | ((du == dl) & ((upper & 1) == 0))
code = selected | (sign_bit << 7)
关键：scale 是按“输出行”取的（每行一个）。这样每一行都能用满 FP8 的动态范围，比全局一个 scale 精确得多。

W8A16：权重是 FP8，计算是 BF16

本项目不是“全 FP8”计算。它把权重存成 FP8 省显存，用的时候在 kernel 里解码成 BF16再做乘加（见 第 8 课 的 gemv/gemm）。行内还支持更细的分块 scale。

// optimized.cu · 解码一行权重（FP8 → BF16 → 乘加）
float weight = __bfloat162float(
    __float2bfloat16_rn( fp8(w[row*K+k]) * scale[row*S + (S==1?0:k/128)] ));
sum += __bfloat162float(x[batch*K+k]) * weight;
S==1 表示“每行一个 scale”；S>1 时每 128 个输入列还有独立的 scale（更细）。
一句话抓住：FP8 量化 = “每个输出行除以一个 scale 变成整数码，存 1 字节；用时再乘回去”。省一半显存，代价是每个数被“取整”到最近的可表示档位。
