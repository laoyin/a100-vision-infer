② 注意力：每个 token 该“看谁”

注意力就是给每个 token 算一份“该关注谁”的权重表。点格子、切开关，看着这张表从原始打分 → 因果掩码 → Softmax 一步步变形。

第一个 token 是“查询 Q”，它去问所有 token 的“钥匙 K”

每个 token 都会投影出三个向量：Q（我要找什么）、K（我能提供什么）、V（我真正携带的信息）。用 Q 和每个 K 点积得到“匹配分”，再归一化成权重，最后按权重把 V 加起来。

1. 投影
q=x·Wq，k=x·Wk，v=x·Wv
2. 打分
score = q·k / √d
3. 掩码
未来的 token 置为 -∞
4. 归一化
softmax → 每行和为 1
5. 加权求和
out = Σ 权重·v
点击任意格子查看那一对 (查询→钥匙)
低高 上三角（虚线格）= 被因果掩码挡住的“未来”

查询 token：— 的注意力分布

点上面网格里的任意一行，这里会画出该 token 把注意力分给了哪些 token。注意它只会分给“自己及左边”的历史。

为什么要有因果掩码？

语言模型是从左往右生成的。计算第 i 个位置时，绝不能偷看第 i+1 个位置（那是还没生成的“未来”）。所以把矩阵的上三角全部设成 \(-∞\)，Softmax 之后它们的权重就变成 0。

本项目里的三个“不一样”

① GQA 分组

24 个查询头，但只有 4 个 K/V 头。每 6 个查询头共享同一份 K/V，省显存。解码时用 gqa_decode kernel 计算。

② 输出门控

注意力结果还要乘一个 gate.sigmoid()——注意力算完，再用一个门决定“放多少出去”。

③ 前缀拼接

解码时 query 只有 1 个，但 K/V 是整段历史。项目用显式 offset 掩码而不是简单 causal=true，以正确处理分块。

对应真实代码 Engine::full_attention()

// 1) 投影出 Q/K/V(+gate)，本项目把它融合成一次 qkv_gate GEMM
q = norm(qg[...,0:D], q_norm);  gate = qg[...,D:2D];
k = norm(proj[...,2HD : 2HD+HK·D], k_norm);
v = proj[...,2HD+HK·D : ...];

// 2) 加位置信息（RoPE，见第 4 课）
q = fused_rope(q, positions, ...); k = fused_rope(k, positions, ...);

// 3) 写入 KV Cache，然后算注意力
out = gqa_decode(q, k, v, state.key, state.value, offset) * gate.sigmoid();
return linear(out, o_proj, reduce=true);   // 输出投影，TP 下要 AllReduce
一句话抓住：注意力 = “打分 → 屏蔽未来 → softmax 成权重 → 按权重加权平均 V”。它就是 token 之间互相交换信息的方式。
