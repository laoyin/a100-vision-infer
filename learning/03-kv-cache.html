③ KV Cache：为什么生成第 100 个字不用重算前 99 个

这是 LLM 推理最核心的加速点。点“生成下一个字”，对比两种做法的代价——右边“有缓存”只算了 1 个 token，左边“无缓存”却把整段历史又算了一遍。

每生成 1 个 token，无缓存要重算整段历史，代价随长度平方级增长；有缓存只需算 1 个。

缓存里到底存了什么

注意力需要用到每个历史 token 的 K 和 V（见 第 2 课）。既然它们算完就不变，那就存下来：新 token 到来时，只把它自己的 K/V 追加到缓存尾部，然后让它的 Q 去和整段缓存的 K/V 做注意力。

// engine.cpp · full_attention()（本项目真实写法）
int old = state.length;
state.key.narrow(0, old, T).copy_(k);      // 把新的 K 追加到第 old 行起
state.value.narrow(0, old, T).copy_(v);    // Value 同理
state.length += T;                          // 长度推进

// 解码时 query 只有 1 个，但 K/V 是整段历史：
out = gqa_decode(q, k, v, state.key, state.value, decode_offset_);
缓存在 struct State{ Tensor key, value; int length; } 里，每个会话、每一层各一份。

线性注意力层用“递归状态”代替缓存

别忘了本项目 64 层里有 48 层是 Gated DeltaNet（线性注意力）。它不存 KV，而是维护一个固定大小的递归矩阵 [H, K, V]（FP32）——不管历史多长，这个状态大小恒定。所以它更省显存，但“记忆”是压缩过的。

full_attention 的缓存

随序列长度线性增长：length × HK × D × 2(K和V)。长文本下是显存大头。用了 GQA，HK 只有 4，已经省了很多。

linear_attention 的状态

大小固定不变：H × K × V 的递归矩阵 + conv 的短历史。代价是注意力被“递归压缩”了。

关键直觉：KV Cache 的本质是“用显存换计算”——把算过的 K/V 留着重复用，避免每生成一个字就重跑整段历史。本项目还在此之上做了前缀缓存（相同开头能直接复用 KV）。
