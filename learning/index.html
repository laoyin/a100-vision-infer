看懂一个 LLM 推理引擎，从这里开始

这套页面把 a100-vision-infer 这个 C++/CUDA 推理引擎里最难懂的概念， 拆成 10 个可交互的可视化。目标只有一个：让你先在脑子里建立 “一次推理时，数据到底怎么从 A 流到 B” 的整体直觉，再回到真实代码去看细节。

先记住这张“总数据流”

图片 + 文字→ 预处理
Python→ Embedding 查表
engine.embed→ 64 层 Transformer
engine.step→ 归一化 + 输出头
engine.logits→ 采样出新 token
worker.sample↺

第 5 步产生的 token 会拼回输入，再走一遍第 3~6 步，如此循环， 直到遇到结束符或达到长度上限。这就是“自回归生成”。

端到端串讲：一次请求 → 一串 token

把前面 10 个主题串成一条线。假设你发来一句话（或一张图 + 一句话）， 引擎内部会经过下面这些站，每一站都能点回对应主题：

① 请求进来 HTTP / SSE

常驻 worker 收到请求，负责编排整个生成循环；答案用 SSE 逐字推回浏览器。

src/worker.cpp · tools/serve.py

② 预处理（多模态） Python

图片切成 patch 过视觉前端，文字过 tokenizer；图文拼成同一段输入 token 序列。

tools/prepare_request.py

③ Embedding 查表

每个 token id 查表变成 [T, 5120] 的隐藏状态——数据第一次“变成向量”。

engine.embed

④ Prefill（吃下整段）

整段输入一次并行过 64 层，顺手写满 KV Cache 与线性注意力的递归状态。

engine.step(T>1)

⑤ 64 层内部

每层：RMSNorm → 混合注意力（3 线性 + 1 全注意力，含 mRoPE）→ SwiGLU；TP=2 时到处 AllReduce。

src/engine.cpp · step()

⑥ 归一化 + 输出头

最后过 RMSNorm，再乘输出头得到 248320 维 logits——每个词一个分数。

engine.logits

⑦ 采样出一个 token

按温度 / top-k / top-p 从概率里挑一个 token（见 第 5 课）。

src/worker.cpp · sample()

⑧ Decode 循环

把新 token 追加进输入，只算这 1 个 token（复用缓存），回到 ⑤ 再走一遍；直到命中 EOS 或长度上限。想更快？见 第 10 课 投机解码。

engine.step(T=1) ↺
一句话总结：Prefill 一次算很多 token（④，算力密集），Decode 每次只算一个（⑧，访存密集）。 这两种负载特性，正是后面 张量并行 与 FP8 量化 针对优化的对象；而 Decode 的访存瓶颈，还能靠 投机解码 进一步摊薄。

怎么用这套页面

1. 先玩，再读

每个页面都有可点的按钮、可拖的滑块。先动手感受，再回来看文字和代码路径。

2. 对照真实代码

每个概念都标注了它对应项目里的哪个文件/函数。看完动画就去 src/ 里找它。

3. 抓住三个灵魂

混合注意力（Full + Gated DeltaNet）、张量并行、FP8 量化——搞懂这三个就懂了大半。

4. 诚实看边界

项目本身还是“实验版、待 A100 验收”。学的是它的设计意图，不是已验证的成熟系统。
