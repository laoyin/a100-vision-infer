第 3 步内部：64 层里藏着两种注意力

整个模型并不是 64 层“一样”的层。它的 layer_types 是一个循环：3 层线性注意力（Gated DeltaNet）+ 1 层完整注意力，重复 16 次共 64 层。下面每一格是一层，点击看它用哪种注意力。

两条路径：Prefill 与 Decode 的差别

Prefill 一次读入 N 个 token

把整段提示词（可能很多 token）一次性灌进网络。数据形状是 [N, 5120]。这一步每个位置都要算注意力，计算量大但只做一次。本项目还会把它切成 chunk（默认 128）分块推进，控制显存峰值。

对应代码：main.cpp 的 prefill 循环 / worker.cpp 每轮推进一个 chunk

Decode 一次只来 1 个 token

生成阶段每次都只处理新产生的 1 个 token，形状 [1, 5120]。历史信息不用重算——存在 KV Cache 里。这一步计算量小但被反复执行，所以引擎会专门为它做 CUDA Graph、批量 decode 等优化。

对应代码：engine.decode() / engine.decode_batch()

把每一阶段对应到真实代码

输入(ids, positions)  →  engine.embed(ids)              // 查表得到 [T,5120]
                      →  engine.step(hidden, positions)  // 64 层循环，见下
                      →  engine.logits(hidden)           // 取最后一个位置，投到词表 [248320]
                      →  sample(logits)                  // 选出一个 token id
                      →  再作为下一轮 decode 的输入 ↺
engine.step() 里每一层做两件事：注意力子层（full 或 delta）+ MLP 子层（SwiGLU），每层都带残差相加。
学完这页，请记住三件事：① 数据是 [token 数, 5120] 的张量；② 它要在 64 层里被反复加工；③ 最后一步选出的 token 会回环成为新输入。接下来就逐块拆开。
