⑪ 深度优化内核：GDN 协作递推 · 卷积+SiLU 融合 · TP2 BF16 归约

第 ⑨ 课讲过 Gated DeltaNet 的递归状态要在寄存器里沿时间步串行扫描；第 ⑥ 课讲过 TP 只在 row-parallel 输出做一次 AllReduce。本轮（commit 6f2c2d0）针对这两处的串行链长度、算子调用次数、通信字节数各做了一刀，并顺带对齐了前端格式与图像传输。本页把三刀拆成可交互的模型。

① GDN 协作递推内核 --gdn-cooperative

原来的 register_scan 是一个线程负责一整列 value：它要把 K 个 FP32 状态全部抱在寄存器里，每个时间步做长度为 K 的串行点积。K=128 时就是 128 个 float 寄存器 + 128 次串行乘加，寄存器压力和串行链都很长。

协作版 cooperative_scan 让同一 warp 里相邻 4 个 lane 共担一列 value：每 lane 只持 K/4 个状态，局部点积后用 __shfl_xor_sync（宽度 4）做子组归约拼出完整结果。串行链与寄存器都降到 1/4。

src/optimized.cu · cooperative_scan()
int h=blockIdx.x, lane=threadIdx.x%4, j=blockIdx.y*32+threadIdx.x/4; float s[K/4]; // 每 lane 只抱 K/4 个状态 for(int t=0;t<T;t++){ for(int i=0;i<K/4;i++){ s[i]*=decay; memory+=s[i]*k[base+4*i+lane]; } // 局部点积 memory+=__shfl_xor_sync(0xffffffff,memory,1,4); // 4-lane 子组归约 memory+=__shfl_xor_sync(0xffffffff,memory,2,4); ... result+=__shfl_xor_sync(0xffffffff,result,1,4); result+=__shfl_xor_sync(0xffffffff,result,2,4); if(lane==0&&j<V) out[..]=__float2bfloat16_rn(result*rsqrtf(K)); }

注意：浮点求和顺序变了，所以默认不开；支持 K=16/128、value 列尾部 tile、以及 MTP 的逐 token 状态轨迹。

② GDN 卷积 + SiLU 融合 --fused-gdn-conv

GDN 的输入投影后要先做 depthwise conv1d 再过 SiLU。未融合时是两个 kernel（conv1d 写中间张量 → silu 再读再写）外加 squeeze/transpose 的开销；融合版 conv_prefill 把两者塞进一个 kernel，并保留中间 BF16 舍入边界，数值不漂移。

③ TP2 BF16 归约 --bf16-tp-reduce

默认 Engine::sum 先把 BF16 投影输出转成 FP32，AllReduce 完再转回 BF16：两次 dtype 转换 + 4 字节/元素的通信量。开启后直接用 ncclBfloat16 做 AllReduce：0 次转换 + 2 字节/元素，通信量减半。但多次 BF16 部分和会引入额外舍入，所以只允许 TP1/TP2，TP4 直接拒绝。

if(options_.bf16_tp_reduce && x.scalar_type()==at::kBFloat16){ ncclAllReduce(out,out,n,ncclBfloat16,ncclSum,comm_,stream); // 直接 BF16 归约 return output; } auto f=x.to(at::kFloat); // 否则 BF16→FP32 ncclAllReduce(f,f,n,ncclFloat,ncclSum,comm_,stream); return f.to(x.scalar_type()); // FP32→BF16

上线前有一个独立两 rank 测试：把 BF16 AllReduce 的精确输出与"FP32 AllReduce 后再 BF16 舍入"逐元素比对，通过才允许跑 benchmark。

④ 本轮其余改动（前端 / 传输）

--frontend-format vllm-string
Qwen 图文消息遵循 vLLM 0.20.1 默认非交错字符串约定（含换行分隔），修正图像后的换行差异；HF 格式仍可用。是格式选择，不是注入 token。
--bf16-patches
直接序列化已舍入的 BF16 像素 patches，请求文件与 host/device 传输字节减半；保留 worker 原有 F32→BF16 输入舍入，不动 FP8 checkpoint。
--frontend-threads N
限制 CPU 预处理线程数（benchmark 用 4），避免过度订阅。
--spool-dir /dev/shm
临时文件放共享内存，减少磁盘 IO；用完即删，不做图像/响应缓存。
三刀的共同思路：缩短串行链（协作递推）、减少 kernel 与中间张量往返（conv+SiLU 融合）、减少通信字节与转换（BF16 归约）。它们都不默认开启，需显式开关并通过数值验收。详见 docs/deep-optimizations.md；相关前置课：⑨ 混合注意力、⑥ 张量并行、⑧ 算子。
