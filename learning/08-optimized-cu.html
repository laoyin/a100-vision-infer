⑧ 算子优化：让 GPU 少跑空路

前七课讲的是“算什么”。这一课讲“怎么算得快”。src/optimized.cu 里有三招：算子融合（一个 kernel 干完几步，省显存往返）、GEMM 分派（小 batch 用 gemv、大 batch 用 WMMA gemm）、寄存器递归（Gated DeltaNet 的状态全程留在寄存器里）。逐节点、逐节看。

第一招 · 算子融合：省掉“写回显存再读出来”

如果一个张量要连过好几步（求平方和 → 归一化 → 乘权重），每步都单独启动一个 kernel，就要把结果写回显存再读出来一遍。融合就是把这几步塞进同一个 kernel，中间结果只活在寄存器/共享内存里。切换下面开关，看 kernel 数量和显存往返怎么变：

对照函数：fused_rms（归一化+乘 weight）、fused_swiglu（silu(gate)×up）、fused_rope（cos/sin+配对旋转一次算完）、conv_decode（卷积+SiLU 一起做）。它们都在 optimized.cu 中。

第二招 · GEMM 分派：按 batch 大小换算法

同样一个“矩阵乘向量/矩阵”，decode 时只有 1 行，prefill 时却有几百行。二者最优的实现完全不同，所以 fp8_linear 里有一句分派：if(M<=8) gemv else gemm。拖动下面的 M，看它切到哪个 kernel：

分派规则来自 optimized.cu · fp8_linear()：if(M<=8) gemv<<<dim3((N+7)/8,M)>>> ... else gemm<<<dim3((N+63)/64,(M+15)/16)>>>

gemv M ≤ 8

一个 warp（32 lane）负责一整行输出：lane 按 stride 32 扫过 K，再用 warp_sum 归约成该行的结果。下图是一个 block 的 8 行。

gemm M > 8

用 WMMA：一个 block 产出 [16,64] 结果，4 个 warp 各算 [16,16]。FP8 权重只在写入共享内存时解码一次。

warp0warp1 warp2warp3
gemv 网格：dim3((N+7)/8, M)，256 线程 = 8 warp → 每个 block 覆盖 8 行。FP8 权重在乘加时被解码：fp8(w[row*K+k]) * scale[...]（回顾 第 7 课）。

第三招 · 寄存器递归：Gated DeltaNet 的状态不出寄存器

本项目的混合注意力里，3/4 的层是 Gated DeltaNet（线性注意力），它靠一个递归状态 state[H,K,V] 逐 token 更新。kernels.cu · scan 是“正确优先”版：状态放在显存里（st[i*V]），每步都要读写显存。optimized.cu · register_scan 把整列 K 个状态塞进寄存器数组 float s[K]，一个线程只负责一个 value 列 j，于是每个时间步都不碰显存。点“下一步”，看状态怎么随 token 演化：

t = 0 / 6 步
点“下一步”开始：每一拍都会先 衰减、算 memory、算 delta、更新状态、最后输出。
核心循环（register_scan<K> 里，K=128 或 16）：s[i]*=decay → memory+=s[i]*k[i] → delta=(v-memory)*beta → s[i]+=k[i]*delta → out=Σ s[i]*q[i]*rsqrt(K)。状态 s[K] 全程在寄存器，只有头尾各读写一次显存。
// optimized.cu · register_scan（递归状态留在寄存器）
float s[K];                                  // ← K 个状态全在寄存器
for(int i=0;i<K;i++) s[i]=state[(h*K+i)*V+j];// 进入时读一次
for(int t=0;t<T;t++){
  float decay=expf(g[t*H+h]), memory=0;
  for(int i=0;i<K;i++){ s[i]*=decay; memory+=s[i]*k[base+i]; }
  float delta=(v[t][j]-memory)*beta[t*H+h];
  for(int i=0;i<K;i++){ s[i]+=k[base+i]*delta; result+=s[i]*q[base+i]; }
  out[t]=result*rsqrtf(float(K));            // 每个 token 输出，不碰状态显存
}
for(int i=0;i<K;i++) state[(h*K+i)*V+j]=s[i];// 退出时写一次
为什么值分块？K 个状态若全在一个线程里，寄存器压力大；所以按 value 列 j 切给不同线程（blockIdx.y*32+threadIdx.x 覆盖 V 列），每个线程只持自己那列的 K 个状态。
一句话抓住：optimized.cu 的优化就三件事——融合（少读写显存）、分派（小 M 用 gemv、大 M 用 WMMA gemm）、寄存器化（递归状态不放显存）。判断一个 kernel 快不快，先看它“被迫”读写了多少遍显存。
